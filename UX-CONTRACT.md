# TopLinkSho interaction contract

Authority: the current user request supplies public content, authorizes a consultation inbox/backend and SMTP integration, and excludes conflicting names and statistics. Preview defaults to noindex; the live HTTPS build enables indexing only with SITE_INDEXABLE=true. This is a single-owner admin application with no public registration.

## Consultation lifecycle

Full name, telephone and consultation subject are required; description and website/social address are optional. Normalize Persian/Arabic digits. Repeat length and field validation on the server. Require same-origin JSON and rate-limit submissions. No public read endpoint exposes leads.

A database write and durable email-queue entry are atomic. A unique submission key makes retries idempotent. Only a committed request produces success and a reference. SMTP failure never undoes a saved request. Private email state and a deliberate retry action belong in admin.

Statuses: new, reviewing, contacted, completed, archived. All changes are reversible. No destructive delete is exposed. Notes are private; versioned updates prevent silent overwrites. Preserve drafts on conflict.

## Admin access

User records own hashed passwords, roles, active/suspended state and session versions. Server-only admin email and scrypt password hash bootstrap an environment-managed account without promoting pre-existing accounts. No default credentials. Authentication creates a random expiring token; store only its hash. Use HttpOnly, SameSite=Lax cookies, Secure in production. Every private page and endpoint checks the session. Logout revokes it; credential rotation invalidates existing sessions. Limit login attempts.

## Navigation and feedback

Main navigation connects `/`, `/about-us`, `/services`, `/contact`; existing service details remain. CTAs lead to a real form. Native dialog semantics own mobile-menu focus, Escape and restoration. Anchors account for the fixed navbar.

Status and page live in URL parameters. Search text may include names and telephone numbers, so it is sent in an authenticated POST body and held only in the admin provider's memory; it does not enter browser history. Search has explicit submit and clear. Server pagination uses twenty items with clamping. The provider preserves the inbox search and private edit drafts across internal navigation; actual document unload warns about unsaved edits. Empty, no-results, configuration, save failure and expired-session states use localized inline feedback.

## Data and operations

MongoDB/Mongoose own leads, users, hashed sessions and shared rate limits. A server-only cached connection and bounded pool are reused. Unique indexes enforce idempotency; optimistic versions protect private edits; TTL indexes clean expired sessions/rate limits while explicit time checks enforce expiry. Passwords are excluded from normal user queries. Credentials remain excluded from Git. SMTP uses TLS/STARTTLS and bounded timeouts. Do not log private request data.

No customer data in URL parameters, analytics or persistent browser storage. The user has not authorized export, destructive retention automation or a deletion policy; none is added.

Every select is rendered by `Select` from option/group data. Values are unique after string conversion. After hydration, Base UI owns the authored single/multiple popup, keyboard/typeahead, touch selection, Escape/focus restoration and collision placement. The portal uses the containing native dialog when present, otherwise the document; it matches the trigger width and stays within the viewport. One native backing select remains the sole named form control and emits native change events to keep `onChange` and `onValueChange` behavior. Controlled values, uncontrolled defaults, resets, option changes, fieldset disabling, loading/errors and refs remain supported. Native refs refer to the backing select; visible focus uses the field id. Pre-hydration and no-JavaScript use keep a native control, and an already-focused native interaction completes before upgrade. Loading/empty messages are Persian; selectable empty items clear filters. GET filters retain URL/default-value behavior. Reduced-motion/weak-device modes remove menu transitions and shadows. Source migration checks reject raw select/option markup outside the shared owner.

## PWA and indexing

Only public HTML and assets can enter the bounded service-worker caches. Admin, API, mutations, RSC and private/no-store responses bypass caching. Offline consultation submission preserves the form and reports failure; no background submission or personal browser storage is introduced. New workers wait for old tabs to close. Install and iOS instructions live in the shared footer. Public metadata and JSON-LD use the same route/service catalog; private pages remain noindex and have no public schema.

## Service navigation and theme

Public navigation includes home, services, blog, pricing, about and contact; case proposals remain a menu shortcut. A native disclosure opens the desktop service directory; Escape/outside press closes it. Ctrl/Cmd+K opens the desktop directory and focuses its first group without taking over shortcuts in editable fields. The mobile dialog preserves its focus, Escape and scroll contract, opens with services visible and contains three native illustrated disclosures. No hover-only access is required. Service search submits a public GET query to /services/search, with clear and no-results states, canonical /services and noindex for search results. The /services catalog stays prerendered and available offline after a visit; search responses stay outside the worker cache. Private inbox searches still remain in POST bodies. Pricing is a request for estimation, with no payment or invented currency conversion. Source case studies are labelled as proposals; the empty source blog does not invent posts.

Desktop hover is an enhancement for fine hover-capable pointers from 1200px. The 70ms opening intent and 170ms exit tolerance prevent accidental flicker; a transparent gap bridge preserves pointer travel. A pointer click pins the disclosure, while Enter/Space toggle it normally. Escape works without requiring focus inside hover content, and never steals unrelated focus. Keyboard focus inside the panel prevents pointer-leave dismissal. Short opacity/transform entry and exit transitions can reverse; closing links become inert immediately. Navigation, breakpoint changes and hidden tabs clear pending work. Reduced-motion and constrained-device modes open and close immediately. Mobile and JavaScript-disabled access retain their existing native semantics.

`theme/theme.json` owns all interface colors. Generated CSS supplies semantic tokens, Tailwind color families and migrated paint values, including private/admin UI and offline fallback. Public breadcrumbs precede the hero and clear the floating navbar. Their current item stays plain text with aria-current; parent links retain full labels. Card lighting uses two static CSS radial gradients with no hard wave edge, blur filter or baked image backdrop. `CardGrid` exposes full SSR content in a desktop grid and a native, keyboard-focusable mobile rail with a visible scrollbar and next-card cue. Rails never autoplay or run an animation loop. `ServiceMenu` owns the owner's newer, compact navigation reference: three illustrated service columns and one promotional column in a single desktop row, with native thumbnail disclosures on phones. ## Project publishing

Owner authorization: the portfolio supports admin-managed projects, media, service assignments, a public list and independent project landing pages. `Project` owns content and publication state. `ProjectEditor` reuses shared form controls; service selection uses native checkboxes and project dates are intentionally typed text. Text is rendered as paragraphs and lists, never raw admin HTML. The owner subsequently requested three complete demonstration projects. These explicitly labelled fictional scenarios are created only by `projects:seed-demo`, with registered public PNG artwork, no video, an immutable demo marker, noindex metadata and sitemap exclusion. Seeding never overwrites an existing project or admin edit and never runs at app startup/build. No fictional project is presented as a real customer claim.

Save a draft before uploading. Draft and archived projects never resolve publicly; authenticated preview is private/no-store/noindex and uses authenticated unoptimized image URLs. Public URLs use `/portfolio/[slug]`; the slug freezes after first publication. Published content alone enters public queries, service cards, metadata, CreativeWork/Breadcrumb/FAQ/video schema and the sitemap. Service ancestors include projects assigned to descendants; service pages use 60-second ISR plus invalidation on saves. Public listing filters/pagination use GET and noncanonical variants are noindex. The portfolio detail intentionally has no loading boundary that could turn missing/draft responses into streamed 200 statuses.

MongoDB GridFS stores project media. Raster images are decoded with pixel/byte limits, rotated, stripped of original metadata and bounded to 2000px WebP. MP4/WebM uploads validate signatures and stream with backpressure/byte limits; downloads support single byte ranges and HEAD. Uploads are one-at-a-time per project under a database lease. Auth/origin checks protect mutations. Version checks prevent silent concurrent edits; a conflict preserves local fields and requires a deliberate choice before retry. The same lease prevents saving references while unused files are deleted. Only explicitly confirmed, unreferenced files may be permanently removed; projects themselves are reversibly archived.

Project drafts live in the admin provider's memory, including new-project identity, and survive internal navigation. Unsaved work or active uploads warns on actual unload and logout; navigating away cancels an active upload and cleans incomplete GridFS writes. Files successfully uploaded but not attached remain available in that project's library. A timeout/error preserves the selected file for explicit retry. Large uploads are cancellable but not resumable; retry restarts the file. Upload limits are 8 MiB per image, 80 MiB per video, and 32 files per project. Node hosting/proxy limits must permit the chosen size and duration.

CMS portfolio HTML bypasses the service-worker page cache so publication changes do not require deployment; offline navigation gets the existing offline shell. Previously public image bytes can remain in ordinary browser/image-optimizer caches. Draft image responses never enter optimization/public caches. Videos use native controls, posters, optional WebVTT captions and no preload/autoplay. Native dialog owns permanent unused-file deletion confirmation; Escape/cancel retains the file.

FAQ native `open` is an uncontrolled browser attribute. Pointer/keyboard interaction or browser history may change it before hydration; only each details element uses `suppressHydrationWarning` to preserve that state, with no suppression on descendants or the document. Choices made before hydration must survive delayed application scripts.

Public navigation uses Next App Router and the existing Link components directly. Next manages server rendering, metadata, history, scrolling, focus and hash destinations. There is no custom route-animation wrapper or page-motion device policy. Public and admin navigation retain their existing layouts.

Below-fold selection fields keep their complete native SSR interface until near the viewport (320px margin), focus or pointer intent. A selection made while the optional popup downloads must survive enhancement; an already focused native field must not be replaced until blur. Performance comparisons use production builds; timing and frame results are local laboratory observations and do not guarantee field Core Web Vitals.

Consultation fields keep their values in native controls, and submission validates FormData directly. Typing before hydration and autofill without React input events must survive later field changes and submit the actual values. Consultation idempotency keys use UUID v4 generated from `crypto.getRandomValues`, which also works on non-HTTPS LAN origins where `randomUUID` is absent. Generation is inside the submit error boundary; failures unlock the form and keep its values. The 15-second request timeout uses AbortController and a cleared timer, without relying on AbortSignal.timeout. A lost response after a committed request retries with the same UUID and returns the same reference. Validation focuses the visible custom select rather than its hidden backing field. Global menu shortcuts ignore events without a string key, composition and form-field shortcuts; document targets are checked safely.
